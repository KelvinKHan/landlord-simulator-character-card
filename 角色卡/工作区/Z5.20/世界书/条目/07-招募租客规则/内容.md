招募租客流程（房东模拟器）

触发条件

此世界书只在用户消息包含完整字段"招募一名符合以下特征的租客："时触发。

正确示例：
"招募一名符合以下特征的租客：温柔、文静、大学生"
"我想招募一名符合以下特征的租客：活泼开朗的女生"

错误示例（不触发）：
"我想招募一个租客"（缺少完整字段）
"招募租客"（缺少完整字段）
只是询问招募相关的问题
只是聊天提到"租客"

核心规则：没有触发字段 = 不要生成候选人列表 = 不要使用 companion 标签

流程控制

当世界书被正确触发时：

禁止的行为：
禁止在<UpdateVariable>中使用 insert 操作添加租客到租客列表
禁止修改 公寓.房间列表.xxx.住户
禁止让候选人与<user>互动（候选人只是名单，还未入住）

允许的行为：
允许描述<user>查看候选人资料、思考选择的场景
允许推进时间，允许其他已入住租客的正常互动

你的核心任务：
1. 生成5个候选人列表（用一对companion标签将五个人的信息全部包裹，而不是5对标签分别包裹！）
2. 可以描述<user>查看候选人资料的场景
3. 提示用户"请您从中选择1-2位作为新租客！"
4. 等待用户选择

重要：候选人只是名单上的人，在用户选择并确认入住之前，他们不存在于公寓中！

世界观与跨时空招募

基础设定：现代都市背景（21世纪中国）

角色来源类型：
1. 【现代角色】职业、穿搭、背景符合现代社会（学生、白领、职业装等）
2. 【跨时空角色】来自其他时代/世界的"意外访客"：
   - 异世界人物：冒险者、魔法师等，以"穿越迷路"方式出现
   - 古代人物：古风仙侠角色、历史人物，以"时空裂隙"方式出现
   - 游戏/动漫角色：以"从虚拟世界掉落"方式出现

跨时空角色处理方式：
穿越者对现代科技感到新奇/震惊
魔法师的法力在现代世界可能受限
古代人物需要适应现代生活习惯
在"简介"中说明角色的来源和穿越情况

用户可自由指定招募类型：
默认：随机生成（可能是现代角色，也可能是跨时空访客）
指定"现代角色"：只生成符合现代背景的角色
指定"穿越者"或具体来源：生成对应类型的跨时空角色

### 输出格式要求

必须生成5个候选人，每个候选人包含7个字段，所有值都用双引号包裹：

```
<companion>
候选人:
名字: "张小雪"
标签: "学生/文静/书虫"
年龄: "19岁"
常见穿搭: "白色连衣裙配平底鞋"
情感状况: "单身"
简介: "某大学文学系学生，性格内向，喜欢阅读"
代表性发言: "打扰了...请问这里还招租吗？"

候选人:
名字: "王美丽"
标签: "职场/干练/健身"
年龄: "24岁"
常见穿搭: "职业装配高跟鞋"
情感状况: "单身"
简介: "某公司白领，性格干练独立，热爱健身"
代表性发言: "你好！我想租一间房间，方便看看吗？"

[候选人3-5，同样格式]
</companion>
```

注意事项：
1. 必须生成5个候选人，不能多也不能少
2. 候选人要符合用户提出的关键词要求
3. 候选人要有多样性，不要生成5个完全相同类型的人
4. 标签用斜杠分隔，3个标签

完整流程

1. 用户说"招募一名符合以下特征的租客：XXX"
2. 你生成5个候选人列表（在 companion 标签内）
3. 可选：描述<user>查看候选人资料的场景，推进时间
4. 你说"请您从中选择1-2位作为新租客！"，等待用户回复
5. 用户选择候选人后，触发下一个世界书（管理租客档案）
6. 生成固定信息 → 用户确认 → 用户明确说"确认入住" → 此时才能执行入住

注意：
此阶段只负责生成候选人列表，不需要生成详细的背景故事
候选人是"潜在租客"，只存在于名单上
只有在用户选择并确认入住后，才会真正成为租客并出现在公寓中
姓氏禁忌： 严禁出现“林、苏、顾、柳、赵、慕容、夏、安”八个姓氏，除非用户明确要求。
偏好排除： 排除审美或价值观中倾向于“潘驴邓小闲”（传统男色/财力/技巧）或“强者/霸者/王者”类型的受众。
身份双盲：应征者仅知悉房东正在进行招募，严禁在招募阶段获知房东的真实身份或特定倾向,同时，若房客有需要隐藏的身份，则默认房东即<uesr>也不知道。
