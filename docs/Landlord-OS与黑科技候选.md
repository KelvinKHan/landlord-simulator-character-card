# Landlord OS 与黑科技功能候选

> 状态：设计储备，尚未进入实现阶段。
>
> 目标：不改变“装修与招募”的主线玩法，通过真实的系统能力、可视化和工程架构，让角色卡呈现出接近独立软件的技术质感。

## 范围硬约束

本项目不以制作通用角色卡框架为目标。候选功能必须满足：

- 离开“房东模拟器”的建筑、房间、装修、租客和跨世界碰撞后，功能本身就不再成立。
- 输入或输出必须直接连接本卡的建筑、房间、租客、世界观、装修或招募数据。
- 通用模块管理、调试、提示词分析等能力只能作为底层技术，不能单独作为主要卖点。
- 科技感必须来自真实的数据联动和代码能力，而不是假终端、背景动画或可以直接由正文口述的内容。

## 当前重点：房东模拟器专属黑科技

### 1. Building Digital Twin｜建筑数字孪生

把当前二维公寓变量自动编译成可旋转、缩放、分层和展开的 2.5D 建筑模型。AI 仍然只需要理解楼层、房间和连接关系，具体坐标、透视和动画全部由代码生成。

数字孪生实时显示房间类型、装修状态、租客位置、灯光、天气和正在发生的事件；医院会表现为病房与科室，写字楼会表现为部门与工位，异世界旅店会表现为客房与功能区。

### 2. Narrative Spatial Sync｜剧情空间同步器

读取最新正文中的人物、地点和动作，将“某租客从卧室前往厨房”等叙述转换成经过校验的空间事件，再让数字建筑中的人物图标真实移动。

同步器只接受建筑中确实存在的房间，发现正文与 MVU 冲突时进入待确认队列，而不是直接污染变量。

### 3. Building UI Compiler｜建筑界面编译器

根据统一建筑 Schema 自动编译专属界面，而不是为每一种建筑手写一整套脚本：

- 公寓：楼层、卧室、公共空间与租客。
- 医院：科室、病房、诊室、员工与病人。
- 写字楼：楼层、部门、办公室、员工与访客。
- 飞船：舱段、岗位、船员与系统状态。

AI 负责生成符合 Schema 的建筑语义，代码负责稳定地生成界面、布局和交互。这项能力只服务本卡未来接管不同建筑的目标。

### 4. Building Nervous System｜建筑神经系统

把新闻、天气、手机消息、租客行为和建筑界面连接到同一个事件对象。一次真实事件只生成一次，然后由不同模块以各自方式呈现。

例如暴雨事件会同时改变窗外天气、房间灯光、租客位置、群聊内容和新闻，但不会让五个模块各自调用 AI 编造互相矛盾的结果。

### 5. Tenant Embodiment Engine｜租客实体化引擎

租客被招募后，自动从人设生成稳定的视觉身份包，包括头像、配色、手机联系人卡片、房间门牌和建筑内人物标记。所有界面引用同一个租客实体，不再各自维护姓名和头像。

如以后接入图片生成，只需要生成一次并缓存；没有图片 API 时也可以用代码生成头像徽章和统一视觉标识。

### 6. Renovation Materializer｜装修具象化引擎

把 AI 输出的装修描述编译成结构化风格令牌、家具类别、材质、颜色和空间标签，再由代码生成房间卡片、缩略图或程序化 2.5D 陈设。

这不会要求 AI 理解像素坐标，也不要求项目提前准备海量素材；AI 决定“装修是什么”，代码决定“如何稳定地显示出来”。

## 已保留方案：Landlord OS｜房东操作系统

Landlord OS 是统一承载掌上公寓、手机、创意工坊、MVU、AI 任务和模块管理的系统中枢，而不是单纯的新皮肤。

核心组成：

- 多窗口桌面：窗口拖动、缩放、吸附、最小化、并排和位置记忆。
- 全局命令面板：通过 `Ctrl/Cmd + K` 搜索并执行系统命令。
- 模块全息图：显示模块依赖、启动状态、加载耗时、能力和错误。
- MVU 观测站：浏览变量、Patch 差异、Zod 验证结果、历史快照和回滚。
- AI 任务中枢：展示“提示词 → 请求 → 解析 → 校验 → 写入 MVU”的真实流水线。
- 更新中心：显示版本、CDN 状态、文件哈希、本地缓存与回滚入口。

建议分期：

1. 桌面外壳、窗口管理器、命令面板。
2. 模块图与真实运行状态。
3. MVU 观测站和时间线。
4. AI 任务中枢与更新中心。

## 通用底层技术储备

以下能力只作为上述房东专属功能的底层支撑，不再单独作为主要功能推进。

### 1. World Blueprint｜世界逻辑蓝图

制作类似 Unreal Blueprint、Node-RED 的可视化节点编辑器。创作者可以把“事件、条件、AI 生成、变量更新、界面通知”连接成一张真正可执行的图。

示例：

```text
收到 AI 回复
  → 检测是否出现新租客
  → 调用额外模型整理档案
  → Zod 校验
  → 写入 MVU
  → 刷新公寓和手机
```

蓝图保存为 JSON，由编译器生成标准事件处理流程。它不是图片展示，而是可以运行、暂停、单步调试和查看每个节点输入输出的程序。

评价：视觉冲击最强，代码含金量高，也能降低以后增加模块的维护成本。

### 2. Prompt X-Ray｜提示词透视仪

捕获真正发送给 AI 的最终提示词，并展示每一段内容来自哪里：角色定义、世界书、聊天记录、EJS 模板、MVU 状态或临时任务。

可提供：

- 世界书触发记录与触发原因。
- 每个来源占用的 Token 数。
- 模板渲染前后对比。
- 本次与上次请求的差异。
- 点击任意段落定位原始来源。
- 提示词过长、重复或互相冲突的诊断。

评价：比假终端更有技术感，能真正回答“AI 为什么会这样回复”。

### 3. MVU Self-Healing｜变量自愈协议

在 JSON Patch 正式执行前先放入影子状态中试运行，通过 Zod 和路径规则检查结果，再决定提交、修复或拒绝。

能力包括：

- 自动创建缺失的父对象。
- 检测对象、数组和原始值之间的类型冲突。
- 把旧版本变量迁移到新 Schema。
- 预览一次 Patch 将修改什么。
- 对危险更新生成修复建议。
- 失败时保留原状态并允许一键重试。

评价：实用性最高，可以直接处理类似 `用户.物品栏` 不存在的问题。

### 4. Memory Neural Graph｜记忆神经图谱

把人物、房间、事件、关系和物品整理成可检索的知识图谱，并在界面中显示为可缩放的动态网络。

底层可以使用 IndexedDB 保存数据，通过向量检索或关键词检索，只把当前剧情最相关的记忆注入提示词。

评价：看起来很炫，也能改善长对话遗忘；但需要处理向量模型、额外 API 消耗和存储升级。

### 5. Parallel Timeline Lab｜平行时间线实验室

在不破坏当前存档的情况下复制完整 MVU 状态，建立多个剧情分支，并比较两个分支的变量和角色变化。

能力包括：

- 从任意快照创建分支。
- 为不同分支设置不同世界观或建筑状态。
- 对比两条时间线的变量差异。
- 选择性合并人物、房间或物品。
- 随时返回主时间线。

评价：技术上非常亮眼，但需要谨慎处理 SillyTavern 聊天文件与 MVU 状态的对应关系。

### 6. Mod Capability Sandbox｜模组能力沙箱

让创意工坊下载的扩展包不能随意访问全部页面，而是必须声明权限：

```text
mvu.read
mvu.write
ai.generate
ui.window
worldbook.install
storage.local
```

系统根据 manifest 提供有限能力，并支持依赖解析、哈希校验、热启停、版本锁定和故障回滚。

评价：工程含金量最高，能把创意工坊从素材库升级为真正的 MOD 平台。

### 7. Multi-Agent Forge｜多智能体锻造台

一次内容生成由多个可替换阶段共同完成，例如：生成者、设定校验者、MVU 结构化处理器和质量评审者。界面显示每个阶段的输入、输出、耗时和结论。

评价：展示效果很强，但会增加副 API 调用次数，应当作为可选高级模式。

### 8. Adaptive Visual Engine｜自适应视觉引擎

从角色头像、壁纸或世界观封面提取主色、明暗和对比度，实时编译 CSS 变量、渐变、辉光、图标配色与窗口主题。

评价：实现周期较短、视觉反馈明显，但技术深度低于蓝图、提示词透视和能力沙箱。

## 初步优先级

如果目标是“第一次打开就觉得很牛”，优先考虑：

1. World Blueprint｜世界逻辑蓝图。
2. Landlord OS｜房东操作系统。
3. Memory Neural Graph｜记忆神经图谱。

如果目标是“真正提升稳定性和维护能力”，优先考虑：

1. MVU Self-Healing｜变量自愈协议。
2. Prompt X-Ray｜提示词透视仪。
3. Mod Capability Sandbox｜模组能力沙箱。
