# v0.3.0-preview.1 实现说明

## 这一版的定位

这一版开始把「多建筑经营界面」升级为只有《房东模拟器》才需要的 Landlord OS。装修和招募仍是主线，新增底层用于让建筑、租客、微信、新闻和正文逐步共用同一个世界状态。

## 新增能力

- 统一任务中心：本地模拟与 AI 结构化生成共用排队、取消、超时、自动重试、手动重试和预览确认。
- AI 安全边界：只在玩家显式启用并主动点击生成时调用酒馆助手；不读取聊天历史，Zod 校验通过后仍只是预览。
- 建筑神经系统底座：接管、装修、招募和探索会向正文、微信、新闻、建筑四个频道同时投递事件。
- 旧模块投递桥：正文获得可注入上下文，微信与新闻获得结构化草稿；只有玩家点击「投递下一条」后才调用旧模块接口。
- 逐步感知：低感知区域不再泄露房间名、用途、设施、人物与装修细节；探索优先补全最未知的区域。
- 租客具身化底座：同一人物拥有稳定的头像键、微信联系人 ID、建筑标记、位置和颜色。
- 建筑数字孪生底座：根据空间尺寸和相邻关系确定性生成不重叠、不越界的可点击楼层布局。

## 不会发生的事

- 切换 AI 模式不会自动生成。
- AI 结果不会绕过玩家确认直接写入 MVU。
- 联动队列不会自动代替玩家发送微信或聊天消息。
- 不会删除原卡界面、美化、世界书、正则和开场白。

## 验证结果

- 完整迁移门禁通过：基线往返无损，22 个原貌模块无遗漏，3 个产品模块进入构建。
- 42 项自动测试全部通过，包含真实 AI 函数阻断、任务状态机、联动投递、感知隐藏、身份一致性和布局不重叠。
- 在线版和离线版仍各自只有 1 条酒馆助手脚本，并使用全新角色卡名和世界书名。

真实 SillyTavern 的自动界面验收因内置浏览器无法继承 Edge 中的本地 Basic Auth 而暂未执行；本轮没有读取或修改认证配置，也没有调用真实 AI。
