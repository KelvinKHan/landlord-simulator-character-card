# v0.3.0-preview.15 实现说明

这一版把“多建筑”从卡片列表升级为可交互的经营版图。它不是静态装饰图：每个节点、链路和数字都由当前 MVU 建筑状态即时计算，接管建筑后网络会随真实状态自动改变。

## 经营版图神经网络

- 总部固定为网络核心，避免建筑增多后失去经营中心。
- 已接管建筑显示为运营节点，并通过发光实线与总部相连。
- 可接管建筑显示为机会节点，并通过流动虚线与总部相连。
- 未发现建筑完全不进入节点和链路，避免提前泄露内容。
- 当前经营建筑拥有单独高亮；节点展示建筑名、状态、空间数和活跃度。
- 点击节点复用现有“进入建筑”与“查看接管提案”动作，没有新增重复控制逻辑。

## 状态与扩展性

- 网络坐标和链路由纯函数确定性计算，同一状态始终得到同一版图。
- 网络是建筑编译器的派生视图，不向 MVU 增加坐标、连线或界面缓存字段。
- 接管完成后，机会节点会自动变为已接管节点，虚线机会链路自动升级为实线运营链路。
- 新建筑以后只要进入现有建筑列表并拥有标准状态，就能自动进入版图，不需要为每栋建筑手写界面。
- 版图统计直接汇总已接管数、运营链路、机会数和真实在场人物数。

## 工程与本地验收

- 自动化回归测试：80/80 通过。
- 新增三项纯函数测试，覆盖默认版图、接管升级和未发现建筑隔离。
- 经营中枢完整流程验证机会节点可进入接管、确认后链路即时升级，装修与招募旧流程继续可用。
- 浏览器验收覆盖明亮与暗色主题、桌面与窄屏布局，并检查横向溢出和空文本。
- 测试期间没有调用真实 AI，也没有发送 SillyTavern 对话。
- 在线版和离线版仍各自只有一条酒馆助手脚本；角色卡和世界书使用独立 `0.3.0-15` 名称。
