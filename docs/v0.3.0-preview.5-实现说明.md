# v0.3.0-preview.5 实现说明

这一版把“招募人物”从创建一张档案，推进为人物真正生活在建筑里的第一层可计算体验。它不引入饥饿、睡眠、卫生等繁琐生存条，而是专注于这张卡最重要的内容：**人物怎样看待你装修出来的空间，以及不同来源的人怎样在同一栋建筑里碰撞。**

## 租客具身生活引擎

- 新增独立“租客生活”页面。
- 从人物职业、性格、来源世界、身份与内心线索中识别自然、创作、安静、社交、科技、异世界奇观、舒适和秩序等偏好。
- 同时读取人物当前所在空间的用途、描述、装修配色、材质、家具、照明、氛围和设施。
- 结合建筑运行脉冲计算人物与当前空间的契合度，并给出能被玩家理解的具体反应。
- 契合度不是全局满意度；同一间房换一个人物，偏好、命中线索和反应都会变化。

## 真实空间建议与相遇

- 引擎会比较当前建筑中实际存在的全部空间，只推荐比当前房间更契合的去处，并显示提升幅度。
- 推荐不会直接移动人物；玩家仍需通过空间同步页确认位置变化。
- 两位以上人物共享空间时，会生成带明确房间定位的共同生活相遇，让关系变化不再悬空发生。

## 确认写入与联动

- 第一次点击人物卡只选择和预览反应。
- 再次确认后，才会把契合度、当前感受、偏好线索、最近空间和反应键写入人物的 `生活状态`。
- 确认会创建“人物感受”事件，并进入正文、微信和建筑三个草稿频道；日常私密感受不会滥发为新闻。
- 感受记录进入当前会话经营回溯，可以撤销和重做。
- 反应记录绑定人物当时的建筑与空间；若确认前人物已移动，系统会要求重新计算，避免错位覆盖。

## 本地验收

- 自动化回归测试：55/55 通过。
- 在线版和离线版仍各自只有一条酒馆助手脚本，原有 22 个启用模块零遗漏。
- 本地 Chrome 已检查租客生活页面：人物卡、契合环、偏好标签、同屋相遇和确认栏显示正常。
- 测试覆盖同房不同人物、真实空间建议、确认写入、三频道联动和人物移动后的过期反应保护。
- 全部测试使用本地状态与模拟任务，没有发送真实对话，也没有调用真实 AI。
- 角色卡、世界书和构建产物使用独立的 `0.3.0-5` 名称，避免与旧版本冲突。
