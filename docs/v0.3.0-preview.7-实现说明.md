# v0.3.0-preview.7 实现说明

这一版补上正文与建筑状态之间最关键的一段连接：剧情里写到人物移动后，不必完全依靠 AI 记忆，也不必每次重新手动选人、选房。系统可以先把文字变成结构化移动意图，再交给既有空间安全链处理。

## 本地剧情提取

- 空间同步页新增剧情片段输入区。
- 本地模式根据 MVU 中真实存在的人物名、建筑名和空间名匹配移动。
- 支持“来到、走进、进入、前往、回到、搬到、抵达、去了、出现在”等明确移动表达。
- 连续句可以沿用上一句已经明确提到的人物，例如“林夏走进花园。随后回到客厅。”
- 会保留“正在观察、准备整理、开始工作”等到达后的活动描述。
- 无法确定人物或空间的句子进入待辨认，不会生成虚假 ID。
- 单纯提到某个房间但没有明确移动词时，不会自作主张移动人物。

## 显式 AI 结构化提取

- 当玩家主动切换到 AI 经营模式并点击“AI 提取意图”时，才允许调用酒馆助手 `generateRaw`。
- 请求只包含玩家粘贴的剧情片段，以及当前可用的人物、建筑、空间 ID 索引。
- 不自动读取聊天历史，不续写剧情，不直接修改变量。
- 输出必须通过 Zod 与 JSON Schema 合同；无把握的句子进入 `unresolved`。
- AI 模式未显式开启时，请求会在生成接口调用之前被拒绝。

## 统一安全边界

- 本地和 AI 提取都只生成空间同步提案。
- 提案继续经过人物存在性、建筑接管状态、空间存在性、同层路线、跨楼层/跨建筑类型和并发位置变化校验。
- 只有玩家点击“确认同步”后，人物位置和房间占用才会原子写入。
- 文本解析错误不会直接污染 MVU。

## 本地验收

- 自动化回归测试：58/58 通过。
- 测试覆盖连续句移动、本地真实 ID、未知人物待辨认、AI 未授权零调用、剧情提案确认和原有手动流程。
- 本地 Chrome 已检查新版空间同步页，剧情输入、模式说明、手动规划和提案队列布局正常。
- 所有自动测试均未调用真实 AI，也没有发送 SillyTavern 对话。
- 在线版和离线版仍各自只有一条酒馆助手脚本，原有 22 个启用模块零遗漏。
- 角色卡、世界书和构建产物使用独立的 `0.3.0-7` 名称，避免与旧版本冲突。
