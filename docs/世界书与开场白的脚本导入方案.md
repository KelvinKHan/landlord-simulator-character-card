# 世界书与开场白的脚本导入方案

## 结论

技术上都能由脚本处理，但不应该把角色卡自带世界书和固定开场白从角色卡里拆掉、改成每次启动再联网导入。

当前推荐架构：

1. 基础世界书、主开场白、备用开场白继续随 PNG/JSON 角色卡发布。
2. GitHub 仓库保留它们的拆分源文件，由构建工具写回角色卡；每个预览/发布版本生成全新的角色卡名和世界书名。
3. 创意工坊继续通过脚本修改“当前聊天”的 ChatLore 和第 0 楼，用于世界观切换。这种修改不污染角色卡模板，也不会影响别的聊天。
4. 以后如需“一键更新整张卡”，可增加用户主动点击的更新器：先显示版本差异和备份提示，再用酒馆助手 `importRawCharacter` 导入新版 PNG。不要在脚本启动时静默自更新。

## 能做什么

### 世界书

- 角色卡 V2 原生支持 `data.character_book`，导入角色卡时会一并带入绑定世界书。
- 酒馆助手支持 `getWorldbook`、`updateWorldbookWith`、`createOrReplaceWorldbook`、`rebindCharWorldbooks` 和 `rebindChatWorldbook`。本项目的租客档案、聊天同步和创意世界观已经使用这类接口操作当前聊天世界书。
- 酒馆助手还支持 `importRawWorldbook(filename, content)`，可以从 GitHub/CDN 获取独立世界书 JSON 后导入或更新。但导入文件不等于自动绑定，仍要明确决定它属于全局、角色还是当前聊天。

### 开场白

- 角色卡 V2 原生支持 `first_mes` 和 `alternate_greetings`；这是固定开场白最稳妥的发布方式。
- 对当前聊天，酒馆助手支持 `setChatMessages([{ message_id: 0, message: '...' }])`，也支持一次设置 `swipes` 或切换 `swipe_id`。创意工坊当前用它切换某个世界观绑定的开场白。
- 如果要永久更新角色卡模板里的开场白，应更新整张卡（例如 `importRawCharacter`），不应只改 SillyTavern 页面中的内存对象。

## 为什么不做启动时自动导入

- 会覆盖玩家自行修改的开场白或世界书。
- 同名世界书、同名角色卡很容易发生错误覆盖或绑定混乱；本项目已经明确要求每版使用唯一名称。
- 脚本本身属于角色卡；它在运行时替换当前角色卡，容易造成重载、重复初始化或半更新状态。
- 网络/CDN 故障会把原本可离线使用的角色卡变成“启动依赖网络”。
- 从远端导入整张卡相当于执行远端携带的新脚本，应该是用户明确触发的升级动作，而不是静默行为。

## 后续可选功能

可以在稳定版以后增加“版本中心”：检查 GitHub 上的版本清单、展示变更、导出当前卡/聊天备份，然后由用户点击“安装新版”。它应使用固定版本或固定提交地址，并保留回滚入口。世界观 DLC 则继续走创意工坊，仅写入当前聊天 ChatLore 和第 0 楼。
