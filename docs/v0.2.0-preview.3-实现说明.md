# v0.2.0-preview.3 实现说明

## 这版能玩什么

玩家打开“房东经营中枢”后，可以看到自己的总部公寓，以及医院、写字楼两个已经有基础楼层和空间的接管机会。复杂经营操作不再占用正文节奏，而是在独立界面完成。

当前可完整体验的闭环是：

1. 选择白塔社区医院。
2. 用本地模拟数据生成三种接管方向。
3. 选定方向并确认，医院正式加入经营版图。
4. 选择旧住院部，生成并应用装修方案。
5. 生成跨世界候选人，把人物安置到指定空间。
6. 在动态记录中查看接管、装修和招募三条结果。

所有步骤都先预览、后确认。取消或只查看方案不会改变正式状态。

## 这版的工程变化

- 新增 MVU 2.0 Zod 数据模型与安全默认值。
- 新增统一 MVU 事务服务、建筑状态服务和本地任务服务。
- 新增通用建筑编译器，同一份数据可以渲染公寓、医院和写字楼。
- 新增完整经营中枢及明暗主题、窄屏样式。
- 多合一构建从 22 个原貌模块扩展为 22 个旧模块加 3 个产品模块。
- 旧界面、旧美化、世界书、正则和开场白仍由角色卡原生携带，没有被新系统替换。

## 为什么暂时只使用本地模拟

这轮的目标是先验证状态、按钮、确认流程和真实 SillyTavern 兼容性，因此任务服务被明确锁在本地模拟模式。它不读取聊天记录，也不调用 `generate` 或 `generateRaw`。

后续接入 AI 时会保留现在的界面流程，只替换“生成候选方案”的数据来源。AI 输出仍需通过结构校验和玩家确认，不能直接写入 MVU。

## 验收门槛

- `npm run migration:check` 必须全部通过。
- 自动化测试必须阻止真实 AI 函数被调用。
- 在线版和离线版必须各自只有一条酒馆助手脚本。
- 旧 22 个启用模块必须全部保留，CSS、HTML、图标和布局不能缩水。
- 每次发布必须使用新的角色卡名、世界书名和产物文件名。
