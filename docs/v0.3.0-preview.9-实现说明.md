# v0.3.0-preview.9 实现说明

这一版让“不同来源的租客在同一栋建筑里发生碰撞”第一次成为不能只靠正文口胡的结构化玩法。关系不是凭空生成：系统必须从 MVU 中确认两个人真的同时占用同一间房，才能编译一份可由玩家确认的关系火花。

## 关系火花如何产生

- 读取同一房间的真实占用者，不依赖正文里是否顺手提到了某个人。
- 综合双方来源世界、职业、性格和内心线索。
- 同时读取相遇空间的舒适度和生活活力，让装修结果实际影响人物碰撞。
- 每条理由都可见，例如跨世界常识差异、不同职业观察视角或主动理解他人的性格倾向。
- 分数只负责解释这次相遇为什么有趣，不会衰减，也不会强制人物关系失败。

## 确认与写入边界

- 推演阶段完全只读，不改 MVU、不调用 AI。
- 玩家先选中火花，再点击“记录关系火花”。
- 写入前再次校验双方位置；任意一人已经离开相遇空间，旧火花立即拒绝执行。
- 确认成功后同时写入 A 对 B 和 B 对 A 的关系，避免单向关系错位。
- 同一次相遇不能重复确认。
- 关系事件只创建正文、微信和建筑草稿，不把私人关系强行变成新闻。

## 界面表现

- “租客生活”页新增独立的 `RELATIONSHIP SPARKS` 区域。
- 卡片显示两个人的视觉身份、关系强度、相遇地点、推演理由和当前已有关系。
- 确认栏明确说明写入内容与联动去向。
- 宽屏与 820px 以下窄屏都没有横向溢出。

## 本地验收

- 自动化回归测试：63/63 通过。
- 新增测试覆盖同处一室才产生、异地不产生、无副作用推演、双向写入、三频道草稿、重复确认拦截和过期位置拦截。
- 浏览器视觉验收确认关系卡、确认栏、原租客具身卡可以在同一页面保持层级清晰。
- 全部测试使用本地固定数据，没有调用真实 AI，也没有发送 SillyTavern 对话。
- 在线版和离线版仍各自只有一条酒馆助手脚本；角色卡和世界书使用独立 `0.3.0-9` 名称。
