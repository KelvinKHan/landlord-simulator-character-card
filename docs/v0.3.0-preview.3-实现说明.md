# v0.3.0-preview.3 实现说明

这一版完成两项直接服务于本卡的底层玩法：**装修具现化**和**叙事—空间同步**。两者都坚持“AI负责创意，代码负责结构”的分工，并且所有自动验收均使用本地模拟数据，没有发送真实对话或调用真实 AI。

## 装修具现化

- 装修方案会被编译成稳定的视觉签名和安全 CSS 令牌。
- 支持木质、玻璃、金属、石材、织物、柔软、自然与超自然等语义材质，以及冷暖、自然和动态照明。
- 配色、家具和材质会同时出现在方案卡片、空间详情和数字孪生房间中。
- 视觉结果由方案内容确定，不依赖随机数；重新打开界面不会无故变样。
- 玩家确认装修或招募后，目标空间视为已经亲自进入并完全感知，避免刚装修好的房间仍显示成未知区域。

## 叙事—空间同步

- 新增独立“空间同步”页：选择人物、目标空间和到达后的活动，先生成本地移动提案。
- 路线引擎会识别同层相邻路径、跨楼层、跨建筑、原地活动和无法确认的未知路线。
- 只有状态为“待确认”的合法提案才可以写入变量。
- 确认时会原子更新人物当前位置与两端空间占用关系，并补充目的地感知。
- 移动只进入正文和建筑频道，避免把日常走动全部广播成微信或新闻。
- 提案记录了创建时的起点；若确认前人物已被其他剧情移动，系统会标记冲突而不是覆盖新位置。
- 已确认移动接入当前会话经营历史，可以与接管、装修、招募和探索一样撤销/重做。

## 工程与兼容性

- 核心新增 `building.renovationVisual`、`building.routes` 和 `landlord.spatialSync` 三项正式服务。
- 在线版和离线版仍各自只有一条酒馆助手脚本。
- 角色卡名、世界书名和构建产物使用独立的 `0.3.0-3` 标识，避免 SillyTavern 同名冲突。
- 原有 22 个启用模块、原版样式和旧功能继续保留。

## 本地验收

- 完整迁移构建与检查通过。
- 自动化回归测试：49/49 通过。
- 使用本地 Chrome 静态渲染检查装修中心、数字孪生和空间同步页面，未发现遮挡、溢出或明显样式退化。
- 真实 SillyTavern 端到端点击验收仍受当前本机 Basic Auth 会话隔离影响；本轮没有读取账号凭据，也没有触发任何真实 AI 请求。
