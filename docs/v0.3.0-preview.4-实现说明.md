# v0.3.0-preview.4 实现说明

这一版让建筑从“可以点击的房间图”进一步变成“会根据当前生活状态产生内容的系统”。重点不是增加成本压力，而是让装修和招募更容易自然长出新场景。

## 建筑运行脉冲

- 新增独立“运行脉冲”页面。
- 从 MVU 中现有的装修完成度、配色、家具、照明、设施状态、空间用途和占用人物实时计算四项建筑体感。
- 舒适体感表示人物是否愿意停留；功能兑现表示设施与用途是否真正可用；生活活力表示人物有没有让建筑运转；空间吸引表示装修有没有形成记忆点。
- 每个空间都有自己的体感矩阵和“高光、顺畅、蓄能、待点亮、需照料”状态，帮助玩家发现下一处值得装修或安排人物的地方。
- 所有结果都是确定性派生数据，不会反向污染原始状态，也不需要调用 AI。

## 协同效应

- 完成装修的空间被人物实际使用时，会出现“人屋共鸣”。
- 良好设施与完整装修结合时，会出现“设施 × 装修”。
- 同一栋建筑容纳两个以上来源世界时，会出现“世界碰撞”。
- 多位人物进入公共空间时，会出现“社交引力”。

这些协同只用于发现更好玩的内容，不增加失败惩罚或复杂账目。

## 可确认的今日场景

- 运行引擎会从真实状态生成“装修第一次被使用、跨世界规则交汇、空间开放亮相、设施高光”等结构化场景。
- 第一次点击只选择和预览，第二次确认才会真正写入。
- 确认后同步更新人物当前状态、建筑今日亮点、建筑事件和正文/微信/新闻/建筑四频道草稿。
- 同一状态下的同一场景只能点亮一次，避免重复刷入事件。
- 点亮场景纳入当前会话经营回溯，可以安全撤销和重做。

## 本地验收

- 自动化回归测试：52/52 通过。
- 在线版和离线版仍各自只有一条酒馆助手脚本；原有 22 个启用模块保持不变。
- 使用本地 Chrome 完成运行脉冲页面视觉检查，指标、空间矩阵、协同卡片和场景区域没有遮挡或明显退化。
- 本轮测试没有发送 SillyTavern 对话，也没有调用真实 AI。
- 角色卡、世界书和构建产物使用独立的 `0.3.0-4` 名称，避免与旧版本冲突。
