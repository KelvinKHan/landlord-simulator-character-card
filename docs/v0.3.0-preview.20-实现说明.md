# v0.3.0-preview.20 实现说明

这一版让“接管更多建筑”和“招募更多世界的人物”真正发生了可计算的关系。跨建筑人才匹配矩阵会把每个人物投影到所有已接管建筑，找到真正适合其生活、工作或世界特质的空间。

## 跨建筑人才匹配矩阵

- 行是现有人物，列是已接管建筑，每个单元格展示该建筑中最适合此人的真实空间。
- 每个单元格显示契合度、最佳空间、相对当前落点的变化，以及命中的偏好标签。
- 人物职业、性格和来源世界与空间装修、设施、用途、运行脉冲和同屋人数共同参与计算。
- 全局最佳落点会高亮；当前已经最合适时，系统会明确告诉玩家不需要折腾。

## 只读流动机会

- 只有移动到另一栋建筑后契合度真正上升的人物才会进入机会列表。
- 机会显示出发建筑、目标建筑、目标空间、提升数值和原因。
- “去空间调度中心”只负责导航；人物移动仍通过原有路线校验、冲突检测和玩家确认。
- 匹配计算全程只读，不调用真实 AI，不写入 MVU，不制造强制任务。

## 逐步感知与性能

- 只评估已接管建筑，可接管或未发现建筑不进入矩阵。
- 只使用充分感知的真实空间，未知楼层不会因为匹配引擎而被泄露。
- 每栋建筑的运行数据只编译一次，再供所有人物复用，避免随人物与空间增加时重复计算整栋建筑。
- 租客具身引擎新增一个稳定的单人—单空间评估接口，矩阵复用同一套偏好规则，不复制业务逻辑。

## 工程与本地验收

- 自动化回归测试：94/94 通过。
- 新增三项纯函数测试，覆盖多人多建筑穷举、职业/世界观导致的跨楼提升，以及未知空间隔离。
- 完整经营流程验证招募人物后矩阵自动出现，并可导航到空间调度中心。
- 浏览器验收覆盖 1440px 桌面、760px 窄屏和 500px 手机布局，无溢出、无 `undefined`、无控制台警告或错误。
- 在线版和离线版仍各自只有一条酒馆助手脚本；角色卡和世界书使用独立 `0.3.0-20` 名称。
