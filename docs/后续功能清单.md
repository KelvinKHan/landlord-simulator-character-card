# 房东模拟器后续功能清单

> 最近确认：2026-08-09  
> 当前基线：Z6.1 Landlord OS / v0.3.0-preview.24  
> 用途：只记录尚未完成或只完成底座的项目。已完成功能以《更新路线图》为准。

## 已锁定的产品决策

1. 装修、招募和不同来源人物与建筑发生碰撞，始终是主线玩法。
2. 公寓始终是初始总部；新接管建筑必须自带基础格局、设施、人员或可玩机会，不能交给玩家从空壳开始。
3. 经营功能以提供爽点和选择为主，不加入房租催缴、破产、每日衰减、繁琐材料税等强制负担。
4. AI 负责创意候选和语义理解，代码负责状态、校验、布局、持久化和联动；AI 输出不能绕过预览与玩家确认直接写入 MVU。
5. **现阶段前端统一沿用现有 Mac 糖果风。** 新功能继续使用圆角窗口、柔和渐变、彩色强调、卡片层级和当前交互语言。主要玩法、页面结构和信息密度稳定后，再统一设计下一代前端。现阶段可以修复布局、响应式、对比度和可读性，但不更换整体视觉风格。

## 状态说明

- **下一阶段**：方向已经确认，应优先设计和实现。
- **底座已完成**：已有可运行版本，但距离完整目标还有明确缺口。
- **设计储备**：已经记录，尚未决定是否值得投入。
- **明确延期**：不是遗漏，当前不占用开发时间。

## 一、下一阶段：玩法和内容

### 1. 长期经营循环

状态：**下一阶段，具体规则尚未定稿。**

需要解决：

- 一次接管、装修和招募完成后，下一轮自然出现什么新乐趣。
- 多栋建筑如何互相提供人物、空间、场景和装修机会。
- 人物组合怎样持续反向改变建筑，而不是只触发一次关系事件。
- 怎样产生收藏、展示、协同和成长感，同时不变成任务清单和生存压力。
- 如何让经营结果持续进入正文、微信、新闻与建筑记忆，形成长期反馈。

验收边界：玩家连续进行多轮装修和招募时，下一步来自已有建筑与人物的新组合，而不是系统强迫完成重复日常。

### 2. 扩充建筑内容

状态：**三栋样例可用，内容规模未完成。**

当前已有总部公寓、医院和写字楼。后续为旅馆、商场、学校、飞船、奇幻旅店及世界观专属建筑补充：

- 基础蓝图、楼层和空间。
- 初始设施、人员与当前状况。
- 可改造区域和立即可玩的机会。
- 建筑专属的招募、装修和事件语义。

### 3. 深化建筑专属界面

状态：**通用编译器已完成第一版，专属表现未完成。**

- 公寓突出房间、租客和公共生活区。
- 医院突出科室、病房、医护人员和患者。
- 写字楼突出部门、办公室、员工和访客。
- 飞船突出舱段、系统、船员和乘客。
- 保持同一建筑 Schema，不为每种建筑复制一套难维护的状态逻辑。

### 4. 真实 AI 模式产品化

状态：**接口、安全边界和本地模拟已完成；真实模型效果尚未验收。**

- 实测接管、装修、招募、剧情移动提取和共创装修。
- 调整结构化提示词和候选质量。
- 验证格式错误、拒答、超时、重试、取消和不同模型兼容性。
- 控制上下文长度，只发送当前任务需要的建筑、空间和人物信息。
- 继续保证生成候选不等于写入 MVU。

在产品负责人明确允许前，自动测试与验收继续禁止调用真实 AI。

## 二、底座已完成但仍需深化

### 1. 2.5D 建筑数字孪生

当前已有确定性二维布局、楼层、房间、连线、装修、人物、运行体感、租客感受和空间记忆图层。尚未完成：

- 缩放、拖拽、楼层展开与折叠。
- 伪立体透视和建筑旋转。
- 人物移动动画和更丰富的程序化家具陈设。
- 天气、灯光和事件直接改变建筑视觉。
- 不同建筑类型的专属空间表现。

### 2. 建筑神经系统深化

当前一个经营事件已能生成正文、微信、新闻和建筑四频道草稿。尚未完成的是让天气、灯光、人物行为、空间状态和剧情上下文同时响应同一事件，并在事件结束后同步恢复或留下记忆。

### 3. 租客完整视觉身份包

当前已有稳定人物 ID、颜色、头像键、联系人 ID、位置和建筑标记。尚未完成：

- 跨界面统一头像或程序化头像。
- 房间门牌、完整联系人卡片和建筑内人物标记。
- 来源世界对应的视觉语言。
- 可选图片生成、一次生成与本地缓存。

### 4. MVU 兼容与自愈

新房东系统已有事务写入、校验和当前会话回溯。尚未完成：

- 自动补齐允许创建的父对象。
- JSON Patch 在影子状态中预演。
- 对象、数组和原始值类型冲突诊断。
- 失败时保留原状态并给出修复建议。
- 更广泛的旧脚本兼容层。
- 处理原开场白中 `用户.物品栏` 等旧结构警告。

### 5. 旧模块正式 API 化

22 个原有启用模块已经原貌进入多合一构建，但仍需逐步迁入统一生命周期、服务容器、事件、存储、日志和错误隔离接口。迁移必须逐个进行，并以视觉和功能不缩水为前提。

## 三、Landlord OS 完整版

状态：**经营控制台和统一任务中心已完成，操作系统外壳未完成。**

- 可拖动、缩放、吸附、最小化和并排的多窗口桌面。
- `Ctrl/Cmd + K` 全局命令面板。
- 建筑、人物、事件、世界包和装修包统一搜索。
- 模块全息图：模块依赖、启动状态、加载耗时、能力和错误。
- MVU 观测站：变量浏览、Patch 差异、Zod 校验、快照和回滚。
- AI 流水线视图：提示词、请求、解析、校验、预览和确认。
- 更新中心：版本、CDN 状态、文件哈希、本地缓存与回滚入口。

这些界面在实现时继续沿用 Mac 糖果风，不提前进行整套视觉重构。

## 四、创意工坊扩展生态

状态：**原有创意工坊保留，扩展包体系未实现。**

- 建筑包、世界观包、租客来源包和装修主题包。
- DLC 世界书及配套开场白的显式安装。
- 扩展包清单、唯一 ID、版本号和依赖信息。
- 安装前预览、哈希校验、兼容提示、本地缓存和故障回滚。
- 玩家主动安装、停用和卸载；启动时不得静默覆盖世界书或第 0 楼。
- 在离线仍可玩的前提下改善在线更新。

## 五、设计储备，尚未承诺制作

- **World Blueprint｜世界逻辑蓝图**：可执行的事件、条件、AI 和变量节点图。
- **Prompt X-Ray｜提示词透视仪**：显示最终提示词来源、触发世界书、占用和差异。
- **Memory Neural Graph｜记忆神经图谱**：人物、房间、事件、关系和物品的可检索网络。
- **Parallel Timeline Lab｜平行时间线实验室**：从快照建立分支、比较并选择性合并。
- **Mod Capability Sandbox｜模组能力沙箱**：权限声明、版本锁定、哈希校验和故障隔离。
- **Multi-Agent Forge｜多智能体锻造台**：可选的生成、校验、结构化和评审流水线。
- **Adaptive Visual Engine｜自适应视觉引擎**：从世界观和素材生成主题变量；应等下一代前端设计阶段再评估。

## 六、明确延期

- 大富翁迁移和重制。
- 音乐系统进一步增强。
- Z5.20 旧存档迁移与兼容。
- 与玩法无关的 localStorage 清理。
- 为所有角色卡服务的通用插件平台。
- 启动时静默远程修改世界书或开场白。
- 只有假终端、背景动画而不改变玩法和数据的伪黑科技。

## 维护规则

1. 新增计划时必须写明服务哪条主线、当前状态和验收边界。
2. 已完成项目移动到《更新路线图》的完成区，本文件只保留未完成部分。
3. 设计储备升级为正式计划前，需要先说明玩家为什么会觉得更好玩。
4. 前端视觉冻结决定如需改变，应由产品负责人明确确认，并一次性更新本文件与《更新路线图》。
