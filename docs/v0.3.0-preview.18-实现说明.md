# v0.3.0-preview.18 实现说明

这一版补齐接管、装修、招募三条主流程中的最后一个确认前预演。玩家选择医院或写字楼的经营方向后，会先看到建筑身份、版图节点、运营链路、感知范围和可玩机会会如何变化，而不是只凭方案文字决定。

## 建筑身份重构预演

- BEFORE / AFTER 面板同时显示建筑旧名称、新名称、旧主题色、新主题色与感知度变化。
- 版图链路面板展示“接管机会 → 运营交通”的升级过程。
- 增量面板显示已接管建筑、运营链路、感知度和显露空间的真实变化。
- 结果面板集中展示新建筑今日亮点、方向摘要、经营标签和可玩机会。
- 若接管提高感知后出现此前不可见空间，会明确列出新显露空间。

## 一致性与安全边界

- 预演复制当前状态，在副本中运行接管变换并重新编译整份经营版图。
- 正式接管和预演共用 `applyAcquisitionDirection`，名称、主题、简介、感知和活跃度不会出现两套规则。
- 预演完成后副本被丢弃，原建筑仍保持可接管状态。
- 已接管、未发现或不存在的建筑不能生成接管预演。
- 只有点击“确认接管”后，系统才会写入建筑状态、当前焦点、接管事件和联动队列。

## 工程与本地验收

- 自动化回归测试：88/88 通过。
- 新增三项测试，覆盖建筑身份与链路升级、预演/正式写入规则一致、不可接管目标拒绝。
- 完整经营流程验证接管预演出现时建筑仍为可接管，确认后原有装修与招募流程继续工作。
- 浏览器验收覆盖桌面与 760px 窄屏接管预演，检查身份变形、版图链路、增量面板和运行错误。
- 测试期间没有调用真实 AI，也没有发送 SillyTavern 对话。
- 在线版和离线版仍各自只有一条酒馆助手脚本；角色卡和世界书使用独立 `0.3.0-18` 名称。
