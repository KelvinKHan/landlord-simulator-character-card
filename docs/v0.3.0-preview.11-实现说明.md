# v0.3.0-preview.11 实现说明

这一版让关系系统从“看见一条线”进一步变成可操作的生活玩法。玩家确认两个人的关系之后，会解锁双人生活导演台；它根据人物差异与真实建筑空间编排共同场景，并在玩家确认后同步改变游戏状态。

## 场景从哪里来

- 只读取当前建筑内已经确认的关系实线。
- 双方来自不同世界时，解锁“跨世界共居实验”。
- 双方职业不同，解锁“双职业联手”的空间共创。
- 若世界和职业都相同，则生成两人自己的共同生活仪式。
- 目标房间来自建筑现有空间；双方已经同处一室时优先延续当前舞台，否则选择运行总分更好的空间。

## 为什么不是正文口胡

- 场景带有稳定 ID、两位参与人物 ID、目标建筑和目标空间 ID。
- 场景记录生成时双方的准确位置，确认时重新比对。
- 任意一人被正文或其他脚本移动后，旧场景无法覆盖新状态。
- 成功启动时，在同一次事务内移动双方并同步旧房间、新房间的占用者。
- 双方人物状态、建筑今日亮点与活跃度一并更新。
- 同一场景不能重复启动；结果进入经营回溯链。

## 联动边界

- 场景编译和选择阶段完全不写 MVU，也不调用 AI。
- 只有玩家点击“启动共同生活”才执行正式变更。
- 成功后创建正文、微信和建筑三类草稿。
- 私人双人生活不会自动进入新闻。
- 后续可以在现有确认边界内增加 AI 文案提供器，不需要改写状态与安全层。

## 本地验收

- 自动化回归测试：68/68 通过。
- 新增测试覆盖关系解锁、跨世界与双职业场景、双方原子移动、状态更新、三频道联动、重复启动拦截和位置过期拦截。
- 动作分发测试确认选择阶段只改界面状态，确认阶段通过经营回溯边界执行。
- 浏览器验收确认两张场景卡、空间分数、选中态和确认栏无 `undefined`，且没有横向溢出。
- 全部测试使用本地固定数据，没有调用真实 AI，也没有发送 SillyTavern 对话。
- 在线版和离线版仍各自只有一条酒馆助手脚本；角色卡和世界书使用独立 `0.3.0-11` 名称。
