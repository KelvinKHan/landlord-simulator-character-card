# 房东模拟器玩家验收流程

> 适用版本：Z6.1 Landlord OS / v0.3.0-preview.24  
> 推荐产物：`房东模拟器Z6.1-LandlordOS-离线技术预览版-v0.3.0-preview.24.png`  
> 预计时间：基础验收约 15 分钟；完整经营闭环约 35～50 分钟。  
> 默认模式：本地模拟，不调用真实 AI，也不需要发送聊天消息。

这份流程按玩家实际看到的顺序编写。它不是开发测试命令清单，也不要求打开浏览器控制台。

## 一、验收前准备

1. 使用安装并启用了酒馆助手（JS-Slash-Runner）的 SillyTavern。
2. 导入 `角色卡/构建产物/房东模拟器Z6.1-LandlordOS-离线技术预览版-v0.3.0-preview.24.png`。
3. 为这张预览卡创建一个全新聊天，不要拿 Z5.20 的旧聊天继续测试；当前没有旧存档迁移。
4. 不需要配置副 API，也不要把任务中心切换成 AI 模式。
5. 如果看到原开场白产生 `用户.物品栏` 或旧租客列表相关 MVU 警告，可以暂时忽略；判断新功能时只看独立的 `房东系统`。

建议不要覆盖旧角色卡。成功导入后，应看到唯一名称：

- 角色卡：`房东模拟器 Z6.1｜Landlord OS·离线技术预览 0.3.0-24`
- 世界书：`房东模拟器·世界书｜Z6.1-LandlordOS-离线-0.3.0-24`

## 二、第一关：导入和原版界面保真

### 操作

1. 打开新聊天，等待开场白和脚本加载完成。
2. 检查正文的彩色文字、卡片、变量更新块和分隔样式。
3. 打开四色悬浮菜单。
4. 依次打开掌上公寓、小手机和创意工坊。
5. 在小手机里随便进入微信、天气、新闻和租客资料，再返回桌面。

### 应看到

- 原来的 Mac 糖果风、粉色窗口、圆角、渐变和卡片层级仍然存在。
- 掌上公寓仍显示楼层、房间二维格子、缩放控件和底部 Dock。
- 小手机仍有完整外框、壁纸和应用图标，不是简陋占位页。
- 创意工坊仍有分类、导入、预设、导出、新建、云端和素材卡片。
- 酒馆助手识别到一条多合一脚本；不是把二十多条脚本重新散装导入。

任意一个旧界面明显缩水、丢失样式或打不开，都算验收失败。

## 三、第二关：进入 Landlord OS

### 操作

1. 从悬浮菜单打开“房东经营中枢”或 `Landlord OS`。
2. 先进入左侧“任务中心”。
3. 确认选中“本地模拟”。

### 应看到

- 左侧包含资产总览、当前建筑、运行脉冲、租客生活、数字孪生、装修中心、招募中心、任务中心、经营回溯、空间同步和动态记录。
- 左下角显示“本地模拟模式 / 不会调用真实 AI”。
- 任务队列初始为空。
- 整体继续沿用 Mac 糖果风，不要求这一版拥有全新的前端风格。

如果显示 AI 模式，先主动切回本地模拟再继续。

## 四、第三关：检查初始建筑版图

### 操作

1. 进入“资产总览”。
2. 查看经营版图神经网络、经营态势雷达、人才匹配和 24H 流线区域。
3. 点击总部公寓节点，再返回资产总览。

### 应看到

- 总部公寓已经属于玩家，不是从空地开始。
- 医院和写字楼显示为接管机会。
- 版图网络区分运营实线与机会虚线。
- 初始人物为 0 时，人才、流线和交汇区域应显示合理空状态，而不是报错。

## 五、第四关：接管医院

### 操作

1. 在资产总览点击医院机会“白塔社区医院”。
2. 点击“生成本地提案”。
3. 阅读三种经营方向，任选一个。
4. 检查接管前后预演，再点击“确认接管”。

### 应看到

- 生成期间任务中心留下建筑接管任务。
- 选中方向前不会修改建筑。
- 预演展示名称、主题、感知度、可见空间和版图链路变化。
- 确认后医院进入已接管状态，当前焦点切换到医院。
- 资产总览变为两栋已接管建筑，医院机会虚线变成运营链路。
- 动态记录中出现接管事件，四频道联动队列出现草稿。

## 六、第五关：探索与逐步感知

### 操作

1. 进入“当前建筑”。
2. 记录三楼或未知区域当前感知度。
3. 点击“探索下一处”一至两次。
4. 再看楼层和空间列表。

### 应看到

- 感知度逐步提高，而不是一次展示全部隐藏信息。
- 新空间或更多描述逐渐显露。
- 探索进入动态记录和经营回溯。
- 未探索内容是未知状态，不会阻止继续装修已知空间。

## 七、第六关：完成一次装修

### 操作

1. 从“当前建筑”点击旧住院部，或进入“装修中心”选择旧住院部。
2. 点击“生成本地方案”。
3. 查看三套装修方案并选择一套。
4. 检查楼层全息投影中的装修前后对照。
5. 点击“应用装修”。

### 应看到

- 方案拥有配色、材质、家具、照明、氛围和后续影响，不只是一段描述。
- 选择阶段只显示投影，不会立即写入状态。
- 投影仍使用旧住院部在真实楼层中的位置和相邻关系。
- 确认后房间的装修风格、材质、配色和描述发生变化。
- 任务中心显示装修任务完成；动态记录和联动队列新增相应内容。

## 八、第七关：招募两位人物

需要两位人物进入同一空间，才能继续验收人物碰撞和共创装修。

### 第一次招募

1. 进入“招募中心”。
2. 点击“生成本地候选人”。
3. 任选一位候选人。
4. 选择旧住院部或其他已知空间作为安置位置。
5. 查看入住预演，再点击“确认加入”。

### 第二次招募

1. 再次生成候选人。
2. 选择另一位尚未招募的人物。
3. 把第二位人物也安排到与第一位相同的空间。
4. 查看预演中出现的室友和潜在关系，再确认加入。

### 应看到

- 候选人包含来源世界、职业、性格、标签和稳定视觉色。
- 入住预演显示人物契合度、建筑脉冲变化、室友与可能激活的协同。
- 确认前人物不会出现在建筑列表中。
- 确认后当前建筑显示两位成员，同一房间显示两位占用者。
- 资产总览的人物数、来源世界数和人才匹配矩阵随之变化。

## 九、第八关：检查数字孪生和建筑脉冲

### 操作

1. 进入“数字孪生”。
2. 分别切换“空间结构”“运行体感”“租客感受”“空间记忆”四个图层。
3. 点击刚才装修并入住的空间。
4. 进入“运行脉冲”，查看四项指标、协同效应和可玩场景。
5. 选择一个尚未发生的场景，预览后点击“确认点亮”。

### 应看到

- 四个图层使用相同房间位置，不会切换后地图错位。
- 空间结构层显示装修和相邻关系。
- 运行体感层显示舒适、功能、活力和吸引。
- 租客感受层只在真实有人物的空间显示反应。
- 空间记忆层显示接管、装修、入住或场景留下的回声。
- 点亮场景后，人物状态、建筑记忆和联动草稿一起更新。

## 十、第九关：人物生活、关系与共创装修

### 操作

1. 进入“租客生活”。
2. 查看两个人对同一房间是否有不同契合度和评价。
3. 任选一份人物感受，点击后确认记录。
4. 找到由同处一室产生的“关系火花”，选择并确认。
5. 在关系星图中查看两个人之间的连线。
6. 选择一个“双人生活导演台”场景并确认启动。
7. 返回“装修中心”。
8. 在页面顶部找到“跨世界共创装修”，生成三案。
9. 选择一案，查看共创装修全息投影，再确认具现。

### 应看到

- 同一房间对不同职业、性格和来源世界的人会给出不同反应。
- 关系火花必须来自真实同处一室的人物。
- 确认关系后才出现稳定关系连线和双人生活场景。
- 双人场景确认后，两人的位置和活动同步改变。
- 共创方案同时读取两位人物和目标空间，不是普通随机装修。
- 确认共创后，人物碰撞永久改变房间装修，并留下空间记忆与联动草稿。

如果当前人物组合没有立即产生可确认项目，可以先在“空间同步”中把两人移动到同一个已知空间，再回到租客生活页。

## 十一、第十关：空间同步与跨建筑移动

### 手动移动

1. 进入“空间同步”。
2. 选择一位人物。
3. 选择总部公寓中的一个已知空间，形成跨建筑目标。
4. 填写到达后的活动。
5. 点击“校验移动意图”，检查路线类型。
6. 点击“确认同步”。

### 本地剧情提取

1. 把人物移回医院，或选择另一位仍在医院的人物。
2. 在剧情片段输入框粘贴一句包含真实人物名和真实房间名的文字，例如：`邵青走进门诊大厅，正在观察这里的访客。`
3. 把示例名字替换成界面里实际存在的人物名。
4. 点击“本地提取意图”。
5. 检查提案后再确认。

### 应看到

- 路线明确区分建筑内、跨楼层和跨建筑移动。
- 生成提案时人物不会立刻移动。
- 确认后旧空间占用、新空间占用和人物位置同时更新。
- 只提到房间但没有明确移动词时，不应该擅自生成移动。
- 不存在的人物或房间不会被猜成有效 ID。

## 十二、第十一关：四频道联动

前面的接管、装修、招募、人物关系和移动已经积累了联动草稿。

### 操作

1. 进入“动态记录”。
2. 查看正文、微信、新闻和建筑四个频道的待分发数量。
3. 先按频道点击“预览本批次”，阅读真正准备投递的内容。
4. 选择少量草稿点击“确认投递”；不必一次发完所有测试数据。
5. 关闭经营中枢，打开小手机微信，检查“房东经营·经营群”。
6. 返回手机桌面打开新闻，检查“今日头条”。
7. 再回到经营中枢查看建筑记录和剩余队列。

### 应看到

- 预览前不会向任何频道写入内容。
- 微信无需提前打开，第一次投递会自动初始化当前聊天数据库。
- 微信群出现与实际经营事件一致的消息。
- 新闻出现相同事件的标题、摘要和“房东经营中枢”来源。
- 建筑频道留下内部经营记录。
- 正文频道只是给下一次生成准备一次性上下文；在本轮无 AI 验收中不需要发送聊天消息。
- 成功投递的草稿从队列移除，失败项仍保留并显示原因。

## 十三、第十二关：经营回溯

### 操作

1. 进入“经营回溯”。
2. 查看接管、探索、装修、招募、移动和人物场景组成的操作链。
3. 对最后一项操作点击“撤销”。
4. 回到对应页面确认状态确实恢复。
5. 再点击“重做”，确认变化重新出现。

### 应看到

- 回溯只影响这次经营操作真正修改的字段。
- 不相关的手机数据、聊天内容和其他脚本状态不会被一起清空。
- 如果状态已经被后续剧情重叠修改，旧操作应拒绝覆盖，而不是强行恢复。

## 十四、第十三关：刷新和持久化

### 操作

1. 记住当前建筑、其中一位人物和一个已装修空间。
2. 关闭经营中枢。
3. 刷新 SillyTavern 页面，重新进入同一个聊天。
4. 再次打开 Landlord OS。

### 应看到

- 当前仍有总部和已经接管的医院。
- 人物、所在空间和装修仍然存在。
- 动态记录、剩余联动队列和经营状态没有回到初始值。
- 多合一脚本正常重新加载，旧的公寓、手机和创意工坊仍可打开。

## 十五、验收结果怎么判断

### 可以通过

- 全程保持本地模拟，没有真实 AI 调用。
- 接管、探索、装修、招募、人物关系和共创装修至少各成功一次。
- 所有确认操作都表现为“先预览、后写入”。
- 数字孪生、微信、新闻、建筑记录读取到同一批经营事实。
- 撤销、重做和刷新后状态正确。
- 原有 Mac 糖果风界面没有明显缩水。

### 应记录为问题

- 点击生成就直接改变正式状态。
- 人物出现在不存在或未感知的房间。
- 数字孪生与当前建筑列表显示不同人物或装修。
- 微信、新闻和建筑记录描述互相矛盾。
- 刷新后接管、装修或人物消失。
- 任一旧界面被替换成明显简陋的占位界面。
- 本地模拟模式下发生模型请求。
- 页面卡死、按钮永久处于加载状态或出现无法恢复的遮挡。

发现问题时，最好记录“所在页面、刚点击的按钮、预期结果、实际结果”和一张截图，不需要提供代码信息。
