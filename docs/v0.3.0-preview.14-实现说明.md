# v0.3.0-preview.14 实现说明

这一版补上多建筑经营里一个很实际的断点：接管医院或写字楼之后，人物不应只能在“当前建筑”内部换房。空间同步现在会汇总所有已经接管的建筑，让玩家可以把人物从总部调度到医院，或从其他建筑送回公寓。

## 多建筑目标列表

- 总部始终进入目标范围。
- 只有“已接管”建筑可以进入目标范围。
- 目标卡显示建筑名、楼层名、空间名、类型、状态和当前/跨建筑标记。
- 未接管写字楼等候选建筑不会因为已经存在于 MVU 就提前成为目的地。
- 只展示建筑编译器当前允许看见的空间，不泄露未知房间。

## 路线与安全边界

- 建筑内同层移动继续按照已知相邻关系计算路径。
- 跨楼层显示“跨楼层通行”。
- 不同已接管建筑之间显示“跨建筑交通”，并写明起点建筑与目标建筑。
- 选择与路线预览阶段不修改人物状态。
- 确认时重新校验人物原位置；旧提案不能覆盖其他剧情的新移动。
- 正式写入仍同步人物位置、旧房间占用、新房间占用和正文/建筑联动。

## 工程与本地验收

- 自动化回归测试：77/77 通过。
- 新增视图模型测试验证总部与医院会进入目标列表、未接管写字楼被排除、建筑和楼层定位完整且结果只读。
- 经营中枢完整流程真实选择医院人物和总部空间，生成跨建筑交通提案，并验证忽略提案不会移动人物。
- 浏览器验收覆盖 1280px 与 760px，多建筑目标列表、选中状态和移动预览没有横向溢出。
- 测试期间没有调用真实 AI，也没有发送 SillyTavern 对话。
- 在线版和离线版仍各自只有一条酒馆助手脚本；角色卡和世界书使用独立 `0.3.0-14` 名称。
