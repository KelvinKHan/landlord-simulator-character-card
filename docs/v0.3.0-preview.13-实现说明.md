# v0.3.0-preview.13 实现说明

这一版开始让租客拥有“想做什么”的主动性，但不会让系统擅自替玩家推进。每个人物会根据自己的职业、性格和建筑真实空间，提出下一步生活行动；玩家批准后才正式移动。

## 人物如何产生想法

- 候选目的地只来自当前建筑已知的真实空间。
- 综合空间舒适、功能、活力、吸引和当前运行状态。
- 摄影、艺术、设计与记录类职业更关注空间表现力。
- 医疗、治疗与疗愈类职业更关注舒适和功能。
- 灵植、园艺与自然倾向会识别花园和绿植空间。
- 好奇、开朗人物更愿意进入公共空间；安静、谨慎人物偏向相对私密的空间。

## 自主不等于自动

- 引擎只生成提案，不写 MVU、不调用 AI。
- 卡片明确显示人物、起点、目的地、职业化活动和选择理由。
- 玩家点击提案只会进入选中状态。
- 只有点击“批准自主行动”才调用现有安全移动事务。
- 确认时会复核人物起点；旧提案不能覆盖其他剧情已经写入的新位置。
- 这是一段生活镜头，不是永久搬家，也不制造强制日程和失败惩罚。

## 状态与联动

- 成功后同时更新人物所在建筑、所在空间和当前活动。
- 从旧房间移除占用，再向目的房间加入占用，避免地图与人物档案错位。
- 行动进入经营回溯，可在当前会话安全撤销。
- 使用人物移动事件生成正文和建筑草稿，不自动制造公共新闻。

## 工程与本地验收

- 自动化回归测试：75/75 通过。
- 新增测试覆盖真实空间选择、职业化活动、不同性格解释、确定性签名、单空间空状态、选择无写入和确认移动。
- 经营中枢完整流程测试真实点击自主行动并验证人物位置改变，测试期间真实 AI 接口继续被硬性禁止。
- 浏览器验收覆盖 1280px 宽屏和 760px 窄屏，两张人物行动卡、路线、分数和确认栏无横向溢出。
- 公共图标、HTML 转义、颜色校验、标签和空状态已从主模板拆到独立模块；主模板 461 行，控制器 495 行。
- 在线版和离线版仍各自只有一条酒馆助手脚本；角色卡和世界书使用独立 `0.3.0-13` 名称。
