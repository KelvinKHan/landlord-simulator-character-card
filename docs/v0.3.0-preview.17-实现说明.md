# v0.3.0-preview.17 实现说明

这一版让招募不再只是读人设和挑房间。选择候选人与安置空间后，系统会临时模拟“这个人真的住进来”，复用现有建筑脉冲、租客具身和关系火花引擎，展示入住第一刻可能产生的真实影响，然后立即丢弃模拟状态。

## 候选人入住预演

- 显示候选人的空间契合分、融入状态和针对目标房间的具身反应。
- 根据职业、性格、来源世界、房间用途、装修、设施和现有使用者解释契合来源。
- 对照入住前后，显示房间活力、房间脉冲、建筑活力和综合脉冲的增量。
- 目标房间中的现有租客会作为真实室友出现，不读取其他房间的人物充数。
- 若候选人与室友满足相遇条件，会预演关系标签、火花分数和潜在相遇对象。
- 新入住可能激活的建筑协同会单独提示。

## 一致性与安全边界

- 预演先复制当前状态，只在副本中临时创建候选人与空间占用。
- 所有数字复用正式运行中的建筑脉冲、租客具身和关系火花引擎，不维护另一套简化公式。
- 计算完成后副本被丢弃；原 MVU、人物列表、空间占用、关系和事件保持不变。
- 未知空间、未接管建筑和重复人物 ID 会在入口处直接拒绝。
- 只有点击“确认加入”后，现有招募事务才正式写入人物、空间与联动事件。

## 工程与本地验收

- 自动化回归测试：85/85 通过。
- 新增三项纯函数测试，覆盖无室友入住、真实室友与潜在关系、未知或未接管目标拒绝。
- 完整经营流程验证预演出现时人物尚未写入，确认后原有招募、装修和联动继续正常。
- 浏览器验收覆盖含两位现有租客的桌面入住预演和 760px 窄屏布局，检查溢出与运行错误。
- 测试期间没有调用真实 AI，也没有发送 SillyTavern 对话。
- 在线版和离线版仍各自只有一条酒馆助手脚本；角色卡和世界书使用独立 `0.3.0-17` 名称。
