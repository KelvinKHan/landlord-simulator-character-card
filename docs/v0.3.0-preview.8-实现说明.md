# v0.3.0-preview.8 实现说明

这一版解决“代码知道建筑真实状态，但正文 AI 不一定知道”这个断层。系统不再粗暴发送整份 MVU，而是为当前建筑编译一份有预算、可预览、只使用一次的上下文胶囊。

## 胶囊包含什么

- 当前建筑名称、类型、世界观和接管状态。
- 建筑运行脉冲总分，以及舒适、功能、活力、吸引四项指标。
- 已知空间的真实 ID、用途、运行状态、综合分和当前在场人物。
- 当前人物的来源世界、职业、真实位置、空间契合度和具身反应。
- 当前建筑最近四条已经确认的经营变化。
- 一致性约束：不得替玩家自动确认操作，不得把未知空间或未确认提案写成事实。

## 为什么不是整份 MVU

- 只编译当前建筑，不包含其他候选建筑和无关状态。
- 不包含界面缓存、任务运行对象、撤销栈或完整联动队列。
- 默认字符预算 2400，可在 800 到 5000 之间限制。
- 达到预算后安全停止添加后续条目，并保持完整 XML 关闭标签。
- 界面显示字符数和 token 粗略估算，玩家能在注入前判断体积。

## 注入安全边界

- 胶囊默认只预览。
- 只有点击“一次性注入正文”才会调用现有酒馆助手正文端口。
- 使用 `injectPrompts` 的 system / depth 0 / once 语义，只影响下一次正文生成。
- 注入胶囊不会直接调用 AI、不会发送消息，也不会写 MVU。
- 正文注入接口不可用时仍可预览，但确认按钮会禁用。

## 本地验收

- 自动化回归测试：60/60 通过。
- 测试覆盖当前建筑隔离、字符预算、未知建筑排除、未确认零注入和显式确认后的一次性端口调用。
- 经营中枢完整流程测试验证了胶囊预览、实际内容和异步注入成功状态。
- 本地 Chrome 已检查展开的胶囊、指标、XML 预览和确认栏，未发现遮挡或布局退化。
- 全部自动测试没有调用真实 AI，也没有发送 SillyTavern 对话。
- 在线版和离线版仍各自只有一条酒馆助手脚本；角色卡和世界书使用独立 `0.3.0-8` 名称。
